# Publishing FlexPass to GitHub and hosting it as a web app

## 1. Create a private GitHub repository

1. In GitHub, select **New repository**.
2. Name it `flexpass-web` (or another name) and choose **Private**.
3. **Do not** initialize the repository with a README, license or `.gitignore` (the source already contains them).
4. Unzip the project locally. Ensure the source root directly contains `frontend/`, `backend/`, `Dockerfile`, `render.yaml` and `README.md`.
5. From that folder, run (replace USERNAME with your own account):

```bash
git init
git branch -M main
git add .
git commit -m "Prepare FlexPass browser MVP for GitHub and deployment"
git remote add origin https://github.com/USERNAME/flexpass-web.git
git push -u origin main
```

Use GitHub authentication/credential management when prompted. Do **not** paste a personal access token into source files or messages. `.env`, SQLite data, build outputs and `specification/` are ignored by Git.

## 2. Deploy using Render Blueprint

1. In your Render dashboard, connect GitHub and grant access to your **private** FlexPass repository.
2. Choose **New → Blueprint**, select the repo and review its `render.yaml`.
3. Review Render's current plan/pricing for the web service **and PostgreSQL** before approving the creation of services.
4. Supply `FLEXPASS_ADMIN_EMAIL` and a **unique 12+ character** `FLEXPASS_ADMIN_PASSWORD` as prompted. `FLEXPASS_SECRET` is generated by Render, and `DATABASE_URL` is connected to PostgreSQL automatically.
5. Allow Render to build the Docker image; after deployment, open its assigned HTTPS URL. Visit `/api/health` to verify database connectivity, `/` for the website and `/login` to use your administrator credentials.
6. Keep `FLEXPASS_DEMO_MODE=false` for a publicly reachable deployment. The database starts without fictitious providers and users in this mode. More onboarding functions must be built before a full pilot.

**Do not enter real personal, HR, financial or bank details** until security, privacy, database migrations, roles, audit logging and business rules are reviewed. This is a software MVP, not a regulated production service.

## 3. Future changes and updates

Make changes in your GitHub clone or through GitHub's web editor, then commit and push. The included **GitHub Actions** workflow runs backend and frontend checks on pushes/PRs. After you connect the repository to a Render Git-backed service with auto-deploy enabled, **each successful push to the tracked branch can initiate a new deployment**. A successful GitHub CI check does not guarantee the hosting deploy succeeded; review the Render Deploys page. Use a staging environment for testing before making changes to a live pilot.

## 4. Hosted fictional demo (optional)

If you want to showcase all three dashboards, you can set `FLEXPASS_DEMO_MODE=true` in Render **before the first database initialization**, and define three unique strong passwords:

- `FLEXPASS_DEMO_ADMIN_PASSWORD`
- `FLEXPASS_DEMO_PARTNER_PASSWORD`
- `FLEXPASS_DEMO_EMPLOYEE_PASSWORD`

The demo emails are shown in README, but no hosted password is embedded in the React build. The default local shared password is rejected for hosted demo initialization. **Only use fictional test data**, because this is not production-hardened.

Changing seeding mode after the database has been populated does not automatically delete existing rows; use a fresh database for isolated demo/production environments. PostgreSQL hosting may incur costs.

## 5. Open items before a production launch

- Validate frontend build and Docker image in a network-enabled CI environment.
- Implement verified invitation/activation, company and partner account onboarding, CSV import, package management, and genuine partner data.
- Make approved transaction, accounting, rollover, expiry and cancellation rules explicit in the backend.
- Add migration management, integration tests with PostgreSQL, backup/restore tests, rate limiting, security/privacy review and monitoring.
- Provide real terms and privacy notices and test mobile responsiveness with a browser.
